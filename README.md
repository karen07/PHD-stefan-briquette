# PHD Stefan Briquette

A CUDA solver for a three-dimensional Stefan problem in a single-briquette geometry. It
models transient heat transfer and phase change on a regular grid using GPU-based finite
differences.

CUDA-решатель трёхмерной задачи Стефана для геометрии с одним брикетом. Моделирует
нестационарный перенос тепла и фазовый переход на регулярной сетке с использованием метода
конечных разностей на GPU.

## Описание

Модель учитывает зависящие от температуры свойства материала и скрытую теплоту вблизи точки
замерзания.

Это исследовательский код, а не универсальный пакет моделирования: параметры эксперимента задаются непосредственно в исходниках, а результаты сохраняются в виде текстовой сводки и снимков VTK для последующей визуализации.

## Разработка и проверка изменений

**Основные точки изменения:**

- `src/briquette.cu` - численная модель, CUDA-вычисления и вывод результата;
- `CMakeLists.txt` - сборка CUDA-программы.

**Файлы сборки:** `CMakePresets.json` определяет профили конфигурации CMake; `CMakeLists.txt` включает CUDA и описывает цель сборки. Изменения численной модели следует вносить в исходники, а не в пресеты.

**Проверка изменений:** При изменении численной схемы проверяйте граничные условия,
шаг по времени и единицы физических величин. Контрольный запуск описан в
разделах "Сборка" и "Запуск".

**Точки изменения численной модели:** `c_ro` определяет объемную теплоемкость
с добавкой скрытой теплоты около температуры замерзания, а `k` задаёт
температурную зависимость теплопроводности. `init` заполняет внутренние
и граничные узлы, `solve` обновляет только внутренние узлы по трем осям.
Изменение физических параметров в `main` нужно согласовывать с этими функциями.
Граничные значения остаются заданными при инициализации двух буферов.

**Ограничения изменения параметров:** буферы GPU и CPU выделяются на
`max_size = 300` по каждой оси, а используемый размер равен
`problem_size = i * 0.01 / dx + 1`. При изменении размера брикета или `dx`
следите, чтобы `problem_size` не превысил выделенный предел. Интервал записи
снимков задаётся выражением `time % ((int)(1 / dt))`; `dt` должен оставаться
положительным и не превышать `1`, иначе выражение может стать некорректным
(в частности, деление по модулю на ноль). Код не проверяет устойчивость
численной схемы автоматически: параметры нужно оценивать отдельно.

**Проверка результата:** Сопоставляйте температуру центра в `out.txt` с
трехмерными снимками `plot/result_<time>.vtk`. В репозитории нет отдельных
автоматизированных численных тестов; устойчивость схемы нельзя вывести только
из успешной компиляции.

## Сборка

Нужны CMake, CUDA Toolkit и совместимый NVIDIA GPU.

```sh
cmake --preset release
cmake --build --preset release
```

Исполняемый файл:

```text
build/release/briquette
```

## Запуск

Перед запуском создайте каталог для VTK-файлов:

```sh
mkdir -p plot
./build/release/briquette
```

Расчет не принимает аргументы командной строки. Размер брикета, температура окружающей среды, шаги по пространству и времени и остальные параметры задаются в `src/briquette.cu`.

## Результат

`out.txt` содержит временную зависимость температуры в центре брикета.
Заголовок колонки в самом файле называет это значение `Maximum temperature`,
но `src/briquette.cu` копирует одну центральную ячейку, а не вычисляет
максимум по всему объёму. Снимки трёхмерного поля сохраняются в ASCII VTK:

```text
plot/result_<time>.vtk
```

Их можно открыть в ParaView или другом VTK-совместимом инструменте.

## Модель

В коде используется трехмерная явная конечно-разностная схема. Теплоемкость и теплопроводность зависят от температуры, а скрытая теплота фазового перехода учитывается через изменение эффективной теплоемкости около температуры замерзания.
